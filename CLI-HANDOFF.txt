本轮操作顺序
1. 用户将 Erase all Secure Boot Settings 设为 Enabled，保存重启。
2. 照片显示 Secure Boot Database=Unlocked、Status=Disabled、User Customized Security=YES；Enforce 灰色；Erase 回到 Disabled。未逐项导出确认四库为空，未读取 SetupMode。
3. 用户按 Restore Secure Boot to Factory Settings 流程恢复；报告重启后安全启动已自动开启。随后照片显示 Windows Boot Manager boot failed 和后续默认设备失败。
4. 用户报告已关掉安全启动。恢复后的 DB 照片显示 7 个证书名称，其中仍有 Windows UEFI CA 2023。没有进行原始字节／指纹前后比较。
5. 在信任文件浏览器先进入 EFI\Boot，看到 bootx64.efi；返回上一级看到 Boot 和 Microsoft，再进入 EFI\Microsoft\Boot，选中 bootmgfw.efi。照片和文字记录能区分这两个目录，但本轮没有重新采集 Boot#### 与分区标识。
6. 用户报告确认添加 bootmgfw.efi 的 hash，开启后仍失败。再次进入 BIOS，DB 照片出现第08条 SHA256，前缀 F2 35 CD 21 C9 19 E0 5D A1 21 8E 8D 13 42 4F ...；不是完整导出值。
7. 用户随后明确补充：重复提示对应 `EFI\\Boot\\bootx64.efi` 与先前已加入的 `EFI\\Microsoft\\Boot\\bootmgfw.efi`，两者哈希相同；10-04 历史报告也曾记录两者当时整文件 SHA-256 相同。本轮没有重新导出完整值或摘要口径。
8. 用户继续做扩大白名单测试：除 `bootmgfw.efi` 外，还信任 `bootmgr.efi`、`memtest.efi`、`SecureBootRecovery.efi`，并信任 `zh-CN` 下可见的所有 `.mui`；`bootx64.efi` 因重复哈希没有新增独立条目。最后 DB 照片可见前7条证书及08～14共7条 SHA256；仍不能把7条逐项绑定到7个具体文件。
9. 再测试后用户只回复“失败”。没有本次新错误截图或日志。不能补写为所有阶段都返回了已独立拍摄的同一错误。

最新状态限制
最后一张 DB 照片在末次失败前。此后是否关回安全启动、进入 Windows、清除手工条目，尚未收到确认。历史关闭安全启动可进 Windows，不等于末次之后已重新验证。不要自行初始化来恢复“干净状态”。
